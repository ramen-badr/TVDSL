# HW1. Лексер Funny: регулярное выражение → НКА → ДКА → минимальный ДКА

## Запуск

```sh
cd solutions/HW01

./hw01 file.funny ...      # то же, но с разбором указанных файлов
```

Код возврата 0 означает, что все прошло успешно. Каждый запуск перезаписывает `dfa.h` в текущем каталоге.

## Где что в коде (`hw01.c`)

Разделы кода идут в порядке пунктов задания, у каждого есть заголовок `Пункт N`.

| Пункт задания | Функция (вызывается из `main` по порядку) |
|---|---|
| 1. Регулярные выражения токенов | `load_tokens` (списки `KW`, `RULES`) |
| 2а. Регулярное выражение → НКА (Томпсон) | `build_nfa` (+ `atom`, `rep`, `cat`, `alt`) |
| 2б. НКА → ДКА (построение подмножеств) | `nfa_to_dfa` (+ `closure`, `find_or_add`) |
| 2в. Минимизация ДКА (Хопкрофт) | `minimize_dfa` |
| 3. Таблица переходов | `export_table` → `dfa.h` |
| 4. Ловушка | `add_trap` (вызывается из `nfa_to_dfa`: ловушка нужна уже при построении ДКА) |
| 5. Тесты | `test_tokens` (массив `TESTS`), `test_examples`; тестовый лексер — `lex` |

## Отчет

### Регулярные выражения

Порядок в списке задает приоритет при совпадении длины: ключевые слова идут раньше `IDENT`. Лексер работает по правилу самого длинного совпадения (maximal munch).

| Токен | Регулярное выражение | Примечание |
|---|---|---|
| `KW_FUNCTION`, `KW_RETURNS`, `KW_REQUIRES`, `KW_ENSURES`, `KW_USES`, `KW_INT`, `KW_IF`, `KW_ELSE`, `KW_WHILE`, `KW_INVARIANT`, `KW_ASSERT`, `KW_ASSUME`, `KW_LENGTH`, `KW_TRUE`, `KW_FALSE`, `KW_NOT`, `KW_AND`, `KW_OR`, `KW_FORALL`, `KW_EXISTS` | само слово, например `function` | ключевые слова |
| `EQ NE LE GE FARROW LT GT ASSIGN` | `== != <= >= => < > =` | операторы |
| `ARROW` | `->\|→` | импликация; `→` — UTF-8 `E2 86 92` |
| `PLUS MINUS STAR SLASH` | `\+ - \* /` | |
| `LPAREN RPAREN LBRACKET RBRACKET LBRACE RBRACE COMMA SEMI COLON BAR` | `\( \) \[ \] \{ \} , ; : \|` | разделители |
| `INT` | `0\|[1-9][0-9]*` | |
| `BAD_INT` | `0[0-9]+` | ошибка: ведущие нули (`00`, `01`) |
| `IDENT` | `[A-Za-z_][A-Za-z0-9_]*` | |
| `WS` | `[ \t\r\n]+` | skip |
| `COMMENT` | `//[^\n]*` | skip |

Набор токенов покрывает всю грамматику из `funny.ru.md`, включая `requires/ensures`, `forall/exists`, `:`, `|`, `->`, `=>`.

### Алфавит и размеры автоматов

Алфавит — байты 0..255, в таблице переходов 256 столбцов. В токенах используются ASCII-символы из правил выше и три байта стрелки `→`, остальные байты вне комментариев ведут в ловушку.

| Автомат | Состояний |
|---|---|
| НКА Томпсона (объединенный) | 309 |
| ДКА после построения подмножеств (только достижимые, включая ловушку) | 129 |
| Минимальный ДКА (Хопкрофт) | 125 (старт `0`, ловушка `1`) |

Минимизация склеивает 4 пары. Три пары — это состояния «первая итерация цикла `*`» и «последующие итерации» в НКА: `"1"` ~ `"10"` (INT), `"A"` ~ `"A0"` (IDENT), `"//"` ~ `"//x"` (COMMENT). Четвертая — концы двух ветвей `ARROW`: `"->"` ~ `"→"`.
Начальное разбиение в алгоритме Хопкрофта строится по метке токена, поэтому разные токены никогда не склеиваются.

### Ловушка

Ловушка соответствует пустому подмножеству при построении подмножеств и после минимизации получает номер `trap = 1`. Таблица полная: для каждого состояния и каждого из 256 байтов задан переход. В ловушку ведут:

- non-ASCII байты вне комментариев (кроме последовательности `→`);
- ASCII-символы, которые не используются в языке: управляющие (кроме `\t \r \n`), `! # $ % & ' " ? @ \ ^ `` ` `` ~ .` (при этом `!=` — допустимый токен);
- недопустимые продолжения токена.

Лексер идет по ДКА до ловушки и запоминает последнюю принимающую позицию. Если такой позиции нет или найден `BAD_INT`, он выводит `ERROR@<смещение в байтах>` и останавливается. Позиции строки и столбца будут в HW2.

Два решения, принятых ради примеров проекта:

- Класс `[^\n]` в `COMMENT` включает non-ASCII, поэтому внутри `// ...` можно писать по-русски.
- Unicode-стрелка `→` из `step12/good_formulas_sorted.funny` и из текста спецификации принимается как `ARROW`.

### Тестирование (`make test`)

1. **Тесты токенов** (массив `TESTS` в `hw01.c`, 87 штук). Покрыты:
   - пустая строка;
   - строки только из пробелов, табов и CRLF;
   - `0`, `00`, `01`, `007` (ошибки), `10`;
   - идентификаторы с `_` и все ключевые слова, а также похожие на них идентификаторы (`functions`, `iff`, `If`, `_if`);
   - все разделители и операторы, `→`, жадные цепочки `<=<>=>`, `===`, `-->`, одиночный `!`;
   - комментарии до конца строки (LF/CRLF), `/` против `//`;
   - non-ASCII и неиспользуемые ASCII-символы (ловушка);
   - две целые программы.
2. **Примеры проекта.** Все 42 файла `project/examples/*/*.funny` разбираются без лексических ошибок. Файлы `bad_*` содержат синтаксические и семантические ошибки, а не лексические.

Результат: `Пройдено тестов токенов: 87/87`, `Файлов без лексических ошибок: 42/42`.

### Как читать таблицу `DFA_NEXT`

Проще всего — по комментарию над строкой. В нем все переходы из состояния записаны символами:

```c
    /* 15: "<" → LT; переходы: '=' → 40 */
    {1,1,1, ... ,1},
```

Это состояние 15: в него приводит строка `"<"`, распознан токен `LT`. По символу `'='` автомат переходит в состояние 40, а по любому другому символу — в ловушку.

Сама строка таблицы устроена так:
- номер числа в строке (с нуля) — код символа;
- число — следующее состояние.

Например, `'='` имеет код 61, поэтому в строке 15 на позиции 61 стоит `40`, на всех остальных позициях — `1` (ловушка, `DFA_TRAP`).

Пример для `"<="`: `DFA_NEXT[0]['<'] = 15`, это `LT`. Затем `DFA_NEXT[15]['='] = 40`, это `LE`.

В лексере: `s = DFA_NEXT[s][(unsigned char)ch]`, пока `s != DFA_TRAP`. Токеном считается последний префикс, на котором `DFA_ACCEPT[s] != 0`.
