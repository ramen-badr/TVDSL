# HW3. Семантические проверки и типы Funny (на парсере HW2)

## Запуск

```sh
cd solutions/HW03
make test              # сборка (dfa.h берется из HW1), затем: 23 синтаксических теста HW2,
                       # 23 семантических теста и разбор всех project/examples/*/*.funny
./hw03 file.funny ...  # полный прогон файлов: аннотированный AST или ошибки с позициями
```

Код возврата 0 — все тесты пройдены. `hw03.c` включает весь front-end из HW2 (лексер на
`dfa.h`, LL(1)-парсер, AST) и добавляет секции HW3; поэтому синтаксические ошибки
диагностируются так же, как в HW2.

## Пример работы

Файл из набора тестов (`project/examples/step05/good_while_basic.funny`, те же дампы
печатает `make test` для каждого файла):

```funny
sum(n:int) returns r:int {
    i = 0;
    r = 0;
    while (i < n) {
        r = r + i;
        i = i + 1;
    }
}
```
```
(function sum (param n int)
  (returns (param r int))
  (block
    (assign (var i) (int 0 :int))        ← i нигде не объявлена: тип выведен (бонус)
    (assign (var r) (int 0 :int))
    (while
      (< :bool (var i :int) (var n :int))
      (block
        (assign (var r)
          (+ :int (var r :int) (var i :int)))
        (assign (var i)
          (+ :int (var i :int) (int 1 :int)))))))
```

Файлы с ошибками вместо дампа печатают диагностику, например `step04/bad_int_condition.funny`:
`3:9: семантическая ошибка: условие if: ожидался bool, получен int`.

## Таблицы символов и проверки имен

Таблицы живут в коде (секция «Пункт 1 (HW3)»): переменные — `Sym syms[256]` со стеком
областей `scope_open`/`scope_close` (одна область на функцию + область квантора; блоки
новой области не вводят), функции и формулы — таблица сигнатур `Func funcs[64]`,
заполняемая первым проходом по модулю (поэтому рекурсия видна). Ниже — их полное
содержимое для программы

```funny
split(x:int) returns a:int, b:int requires x > 0 { a = x; b = x - a; }
main() returns r:int { p, q = split(9); r = p * q; }
```

**Таблица сигнатур модуля** (`funcs`, собирается до проверки тел):

| Имя | Вид | Параметры | Возвраты |
|---|---|---|---|
| `split` | функция | `x: int` | `a: int`, `b: int` |
| `main` | функция | — | `r: int` |

**Таблица символов (переменные, `syms`)** — по областям; при проверке
тела `split` в ней три строки, при проверке тела `main` — три (стек: область функции
открывается после `requires`, закрывается в конце тела):

| Область | Имя | Тип | Доступ | Откуда |
|---|---|---|---|---|
| функция `split` | `x` | `int` | только чтение | параметр |
| функция `split` | `a` | `int` | чтение/запись | возврат |
| функция `split` | `b` | `int` | чтение/запись | возврат |
| функция `main` | `r` | `int` | чтение/запись | возврат |
| функция `main` | `p` | `int` | чтение/запись | локальная, тип выведен из кортежа `split` (бонус) |
| функция `main` | `q` | `int` | чтение/запись | локальная, тип выведен из кортежа `split` (бонус) |

Внутри квантора открывается вложенная область с его переменной (в примере нет).

**Таблица проверки имен** — что и где проверяется, все сообщения с позицией узла:

| Проверка | Сообщение | Код | Тест |
|---|---|---|---|
| повторное объявление переменной (параметр/возврат/`uses`/квантор) | `повторное объявление 'x'` | `sym_add` | «повторный параметр» |
| повторное имя функции/формулы в модуле | `повторное объявление 'f'` | `check_module` | «повторная функция» |
| объявление имени встроенной `length` | `'length' — встроенная функция` | `check_module` | — |
| неизвестное имя в выражении (в т.ч. использование до объявления) | `неизвестное имя 'x'` | `type_expr`, N_VAR | «неизвестное имя», `bad_unknown_identifier`, `bad_ensures_unknown`, `bad_invariant_undeclared` |
| использование `uses`-локальной до первого присваивания | `использование 't' до первого присваивания` | `type_expr`, N_VAR | «использование до присваивания» |
| неизвестная функция/формула в вызове | `неизвестная функция 'foo'` | `check_stmt`, `type_expr` | «неизвестная функция», `bad_unknown_function` |
| запись в параметр (`x = e` и `a[i] = e`) | `запись в параметр 'x'` | `assign_to`, `check_stmt` N_UPDATE | «запись в параметр», `bad_modify_param`, `bad_modify_param_array` |
| неизвестное имя в левой части `a[i] = e` | `неизвестное имя 'a'` | `check_stmt`, N_UPDATE | — |

Все проверки — в секции «Пункт 2-3. Проверка типов и унификация» (`hw03.c:620`):

| Аспект критерия | Код | Тесты |
|---|---|---|
| выражения и операторы | `type_expr` — правила для `+ - * /`, сравнений, `not/and/or/->`, унарного `-`, индексации, `length`, кванторов | «int[] в арифметике», «индекс не int», «length от int», «формула в арифметике», «логические операции» |

| функции (вызовы) | `check_args` — число и типы аргументов против сигнатуры; `type_expr` N_CALL — функция с несколькими возвратами в выражении запрещена; `check_stmt` N_MASSIGN — длина кортежа = числу возвратов | «неверное число аргументов», «мультивозврат в выражении», «кортеж неверной длины», `bad_arg_count`, `bad_formula_arity`, `bad_arg_mismatch_recursion`, `bad_minmax_tuple_use` |
| параметры/возвраты (явные типы) | `check_decl` — параметры и возвраты попадают в таблицу символов с типом из объявления (аннотация обязательна грамматикой HW2); присваивание в возврат — через `assign_to` | «кортеж и вызовы», все `good_*` с контрактами |
| локальные с явным типом | `check_decl` N_USES — `int`/`int[]` из аннотации; `assign_to` унифицирует присваиваемое (конфликт — ошибка), без аннотации — вывод из первого присваивания (бонус) | «uses с аннотацией и выводом», «конфликт вывода типа», `bad_modify_param` (запись в параметр) |

## Бонус: вывод типов локальных без аннотации

Реализация: `assign_to` — имя слева от `=`, которого нет в таблице символов, объявляется
с типом правой части; `uses`-локальная без аннотации хранится как `TY_NONE` и
конкретизируется первым присваиванием (`unify`). Демонстрация — переменная `i` нигде
не объявлена, но после первого присваивания всюду имеет выведенный тип:

```funny
main() returns r:int { i = 0; while (i < 3) i = i + 1; r = i; }
```
```
(assign (var i) (int 0 :int))          ← первое присваивание задает тип
  (while (< :bool (var i :int) …)      ← дальше i уже int
    (assign (var i) (+ :int (var i :int) (int 1 :int))))
```

Обе части формулировки бонуса проверены тестами (`SEMT`):

| Часть условия | Тест | Результат |
|---|---|---|
| тип по первому корректному присваиванию | «вывод типа локальной», «uses с аннотацией и выводом», «кортеж и вызовы» (`p, q = split(9)`) | `p`, `q`, `i` — `int` в дампе |
| противоречия = ошибка | «конфликт вывода типа» (`t = 1; t = a;`) | `несовместимые типы: int и int[]` |
| невозможность вывода = ошибка | «использование до присваивания» (`uses t`, `r = t + 1` до присваивания) | `использование 't' до первого присваивания` |

Вывод из кортежа работает и на примерах проекта: `good_chain_multi`, `good_minmax_normalize`.

## Типы и правила (отчет)

Типы (выбранное подмножество): `int`, `int[]`, `bool` — последнее только для условий и
предикатов; отдельных переменных типа `bool` в Funny нет. Типы `string`/`func` не
поддерживаются (в Funny их нет). Неявных приведений нет — только равенство типов.

| Конструкция | Правило |
|---|---|
| `INT`, `-e`, `+ - * /` | `int` (операнды `int`) |
| `true`/`false`, `not`, `and`/`or`/`->` | `bool` (операнды `bool`) |
| `== != < <= > >=` | `bool` (оба операнда `int`) |
| переменная | тип из таблицы символов |
| `a[i]` | `a: int[]`, `i: int` → `int` |
| `f(...)` | сигнатура: число и типы аргументов; в выражении — функция с одним возвратом; вызов формулы — `bool` |
| `length(a)` | `a: int[]` → `int` |
| `r = e;` | `e` совместим с типом `r`; запись в параметр запрещена; локальная без `uses` здесь объявляется (бонус) |
| `a[i] = v;` | `a` — изменяемая `int[]`, `i: int`, `v: int` |
| `p, q = f(...);` | число переменных = числу возвратов, типы попарно |
| `if`/`while`/`assert`/`assume`/`invariant`/`requires`/`ensures`/тело формулы/квантора | `bool` |

Области видимости: модуль (функции/формулы, имена уникальны, `length` занята),
функция (параметры только для чтения + возвраты + `uses`-локальные, имена уникальны,
блоки новой области не вводят), квантор (своя переменная). Сигнатуры собираются
первым проходом — рекурсивные вызовы корректны. Использование до объявления
диагностируется при обходе в порядке следования: неизвестное имя либо (для
`uses`-локальной) «использование до первого присваивания».

Унификация (`unify`): `TY_NONE` — переменная, конкретизируется первым известным
типом; конфликт — `TY_ERR`. Это и есть бонус-вывод типов локальных: тип берется из
первого корректного присваивания, противоречие — ошибка «несовместимые типы».

## Аннотированный AST

Дамп как в HW2, но у каждого выражения стоит вычисленный тип (`ty` узла):

```
(assign (var r)
  (+ :int (var i :int) (int 1 :int)))
```

Формат пригоден для HW4/проекта: типы выражений уже на узлах, позиции (`line`/`col`)
сохранены. Печать включается флагом `annot` после успешной проверки (`analyze`).

## Диагностика

Формат: `строка:столбец: семантическая ошибка: <описание>`; позиция — узел AST.
Проверка не останавливается после первой ошибки (обход продолжается), но и не
плодит каскады: выражение с ошибкой получает `TY_ERR`, и операторы над ним молчат
(например, `r = foo(1) + 2` при двухвозвратной `foo` дает одну ошибку, а не три).
Лимит — `MAXSEM` ошибок.

## Отклонения и ограничения

- `step05/good_while_nested.funny` записывает в параметр `n`, что противоречит
  `funny.ru.md` («параметры только для чтения») — по спецификации это ошибка, тест
  ожидает ее (единственный `good_*`-файл с ожидаемой ошибкой);
- «чтение неинициализированного — неопределено» (funny.ru.md) не проверяется: это UB,
  а не ошибка типов; использование до первого присваивания проверяется только для
  `uses`-локальных;
- семантика `->` в предикатах и единственная иерархия выражений унаследованы от HW2;
- вложенное `a[i][j] = v` не разбирается еще в HW2 (синтаксическое ограничение).
