## Где что в коде (`hw02.c`)

Разделы идут в порядке пунктов задания, у каждого заголовок.

| Пункт задания | Функция (вызывается из `main` по порядку) |
|---|---|
| 1. Ветка LL(1) | зафиксирована в баннере секции «Пункт 1-2»; отдельного кода не требует |
| 2. Грамматика LL(1), приоритеты | `parse_decl`/`parse_stmt`/`parse_assign` и пирамида выражений `parse_expr` → `parse_or` → `parse_and` → `parse_not` → `parse_cmp` → `parse_arith` → `parse_term` → `parse_unary` → `parse_primary` |
| 3. Лексер HW1 с позициями | `lex_all` (+ `code_of`, таблица `TNAME`); таблица переходов — `dfa.h` |
| 4. AST и вывод | пул узлов `node`/`lexstr`/`add`, печать `pnode`/`dump`, полный разбор `parse_program` |
| 5. Ошибки: позиция + режим паники | `got_desc`/`synerr_txt` (сообщение с позицией, лимит `MAXERR`), `check`/`eat`/`expect`, `panic_stmt`/`panic_decl` |
| 6. Тесты | `test_ast` (массив `TESTS`, 23 шт.), `test_files`; вход — `parse_program` |

Общие типы и состояние (коды токенов, `Tok`/`toks`, `Node`, состояние ошибок) вынесены
в блок «Общие объявления» перед п.1 — они нужны сразу нескольким пунктам. Каждая
функция определена в том пункте, которому она требуется по заданию; поскольку разбор
(п.1-2) стоит выше секций п.4 и п.5 и вызывает их средства, в начале п.1-2 стоят
прототипы этих функций — единственный способ в C при таком порядке (плюс взаимно
рекурсивные `parse_*`, как `alt()` в hw01.c).

Ключевое LL(1)-преобразование: `function`-объявление и формула имеют общий префикс
`имя ( параметры )` — он вынесен в `parse_decl`, а развилка перенесена на следующий токен
(`=>` формула / `requires`|`returns` функция). Левая рекурсия выражений устранена
пирамидой приоритетов. Условия и предикаты сведены к одной иерархии выражений — иначе
`"(" условие ")"` и `"(" выражение ")"` дают конфликт FIRST.

## Грамматика (финальная, LL(1))

Терминалы в `"кавычках"` (ключевые слова и знаки), плюс `IDENT` и `INT`; `ε` — пустая
строка. Начальный символ `module`. Разбор — по одному токену вперед (LL(1)):
множества FIRST альтернатив каждого правила не пересекаются.

```EBNF
module    = decl { decl } EOF ;

decl      = [ "function" ] IDENT "(" [ varDefs ] ")" declTail ;
declTail  = "=>" expr ";"                                            (* формула *)
          | [ "requires" expr ] "returns" varDefs
            [ "ensures" expr ] [ "uses" localDefs ] stmt ;           (* функция *)

varDefs   = varDef { "," varDef } ;
varDef    = IDENT ":" type ;                     (* параметры и возвращаемые значения *)
localDefs = localDef { "," localDef } ;
localDef  = IDENT [ ":" type ] ;                              (* тип можно опустить *)
type      = "int" [ "[" "]" ] ;                                       (* int или int[] *)

stmt      = block | ifStmt | whileStmt | assertStmt | assumeStmt | assignment ;
block     = "{" { stmt } "}" ;
ifStmt    = "if" "(" expr ")" stmt [ "else" stmt ] ;          (* else — к ближайшему if *)
whileStmt = "while" "(" expr ")" [ "invariant" expr ] stmt ;
assertStmt= "assert" expr ";" ;
assumeStmt= "assume" expr ";" ;

assignment= IDENT assignTail ;
assignTail= "[" expr "]" "=" expr ";"                             (* a[i] = v — сахар *)
          | "=" expr ";"                                              (* r = выражение *)
          | { "," IDENT } "=" IDENT "(" [ args ] ")" ";" ;        (* кортеж: p, q = f(...) *)

args      = expr { "," expr } ;

expr      = orE [ "->" expr ] ;                 (* импликация правоассоциативна *)
orE       = andE { "or" andE } ;
andE      = notE { "and" notE } ;
notE      = "not" notE | cmp ;
cmp       = arith [ relOp arith ] ;             (* одно сравнение, неассоциативно *)
arith     = term { ("+" | "-") term } ;
term      = unary { ("*" | "/") unary } ;
unary     = "-" unary | primary ;
primary   = INT | "true" | "false" | quant | IDENT primaryTail | "(" expr ")" ;
primaryTail = { "(" [ args ] ")" | "[" expr "]" } ;      (* вызов и/или обращение a[i] *)
quant     = ("forall" | "exists") "(" IDENT ":" type "|" expr ")" ;

relOp     = "==" | "!=" | "<=" | ">=" | "<" | ">" ;

letter    = "A" | ... | "Z" | "a" | ... | "z" ;
digit     = "0" | ... | "9" ;
digit1    = "1" | ... | "9" ;

IDENT     = ( letter | "_" ) { letter | digit | "_" } ;
INT       = "0" | digit1 { digit } ;
```

Приоритеты операций (от низшего к высшему), правоассоциативна только импликация:
`->` < `or` < `and` < `not` < сравнения (`== != < <= > >=`, неассоциативны) <
`+ -` < `* /` (левоассоциативны) < унарный `-`.

Обессахаривание: `a[i] = v;` разбирается в узел `update` и означает `a = set(a, i, v);` —
функциональное обновление с копированием массива (семантика из `funny.ru.md`).

Отклонения от `funny.ru.md` (задание требует их документировать):

- условие и предикат сведены к одной иерархии `expr`: исходные правила
  `"(" условие ")"` и `"(" выражение ")"` не LL(1) — `(` начинает и группу условий,
  и выражение сравнения (например `(1+2)*3 < 4`); ошибки «условие не булево» и
  «assert не предикат» из примеров проекта — семантические, парсер их сознательно
  пропускает;
- необязательное ключевое слово `function` перед объявлением: в `funny.ru.md` его нет
  в синтаксисе, но оно есть в лексере HW1 и в примерах P02/P03 — принимаются оба варианта;
- пустой модуль (пустой ввод) — ошибка «ожидалось объявление функции или формулы»;
- импликация `->` разрешена и в предикатах (assert/invariant/кванторах), а не только в
  условиях: этого требует пример `step12/good_formulas_sorted.funny`;
- вложенное обновление `a[i][j] = v` не поддерживается (в примерах проекта не
  встречается, обессахаривание требует временной переменной — оставлено следующим шагам);
- кортежное присваивание допускает ровно один вызов справа (по грамматике `funny.ru.md`).

## Формат AST

Текстовый S-подобный дамп: узел — `(вид атрибуты дети…)`; дети-листья остаются на строке
родителя, вложенные — с отступом. Каждому узлу сопоставлены позиция (строка, столбец) —
поля `line`/`col` в `hw02.c`, они понадобятся следующим HW (P05: привязка ошибок к узлам).

```
(function add (param a int) (param b int)
  (returns (param r int))
  (block
    (assign (var r)
      (+
        (call add (var a) (var b))
        (neg (int 1))))))
```

Виды узлов и их дети:

| Узел | Дети | Смысл |
|---|---|---|
| `function имя` | `param`*, `requires`?, `returns`, `ensures`?, `uses`?, оператор | объявление функции |
| `formula имя` | `param`*, выражение | определение формулы (`=> …;`) |
| `param x int[]?` / `local x int[]?` | — | переменная с типом (`local` может быть без типа) |
| `requires`/`ensures`/`invariant` | выражение | предусловие/постусловие/инвариант (по умолчанию `true`/`false`/`true`) |
| `block` | операторы | блок |
| `assign` | `var`, выражение | `r = e;` |
| `update` | `var`, индекс, выражение | `a[i] = v;` — сахар для `a = set(a, i, v);` (функциональное обновление с копированием) |
| `massign` | `vars`, `call` | кортежное присваивание `p, q = f(...);` |
| `if` | условие, then, `else`? | `else` связывается с ближайшим `if` |
| `while` | условие, `invariant`?, оператор | цикл |
| `assert`/`assume` | выражение | проверка/допущение |
| `int N`, `var x`, `true`, `false` | — | литералы и переменная |
| `call f` | аргументы | вызов функции или ссылки на формулу (`length` — встроенная) |
| `index` | база, индекс | `a[i]`, вкладывается: `a[i][j]` |
| `+ - * / == != < <= > >=`, `and`, `or`, `->` | два операнда | бинарные операции; знак — тег узла |
| `neg`, `not` | операнд | унарные |
| `forall`/`exists` | `param`, тело | квантор |

## Ошибки и восстановление

Формат сообщения: `строка:столбец: ожидалось X, получено Y` (для имени и числа — с лексемой:
`получено имя 'r'`). Лексические ошибки тем же форматом: нераспознанный символ, число
с ведущим нулем — разбор файла на этом прекращается.

Режим паники (LL): по ошибке сообщение печатается, и разбор уходит на ближайшую точку
восстановления — внутренний блок или модуль (`setjmp`/`longjmp`), где пропускаются токены
до синхронизирующего: на уровне оператора — `;` (поглощается), `}`, конец файла; на уровне
модуля — `;`, начало следующего объявления, конец файла. Разбор продолжается, поэтому
в одном файле сообщается несколько ошибок; после 20 ошибок — остановка («слишком много
ошибок»). Зацикливание исключено: каждая ошибка либо поглощает ≥1 токен, либо выходит
из цикла разбора — проверено на мусорных входах (`}}}{{{`, `((((((` и т.п.).

Пример:

```text
main() returns r:int {
    r = 1 + 2  // отсутствует точка с запятой
}
```
→ `3:1: ожидалось ';', получено '}'` — паника останавливается на `}` (не поглощая его),
блок корректно закрывается, ошибка одна.
